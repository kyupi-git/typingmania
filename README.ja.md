# TypingManiaNovel

[简体中文](README.md) | [English](README.en.md) | **日本語**

**バージョン：20260726**

[変更履歴](CHANGELOG.md) · [20260726 リリースノート](docs/releases/20260726.md)

TypingManiaNovel は
[TypingMania NEO](https://github.com/innocenat/typingmania)
をベースに再開発した、多言語対応の歌詞タイピング音楽ゲームです。中国語・英語・日本語の楽曲、ローカル実行と静的サイトでのプレイ、Keyfall、オートデモ、ライブラリ管理、QQ Music・NetEase Cloud Music・Apple Music・ローカルフォルダーからの取り込みに対応しています。

> **曲を追加して自動でプレイ可能にできます：** QQ Music のキャッシュとダウンロード、NetEase の完全なダウンロードとキャッシュ、ログイン中の Apple Music アカウントで再生できるリンク、選択したローカルフォルダーを、検証済みのオフライン曲へ自動変換します。個別に利用制限された曲には、そのアカウントの再生権限が必要です。

## すぐに遊ぶ

### Windows x64

1. Release の ZIP をダウンロードして展開するか、リポジトリ全体をクローンします。
2. `start-game.cmd` をダブルクリックします。
3. Edge またはモダンブラウザーでプレイします。

インストール不要のワンクリック起動は、現在 Windows x64 のみ対応しています。その他の OS でも、次の手順で Node.js を用意すれば実行できます。

初回起動時は、同梱の Node.js ランタイムを検証して展開し、このプロジェクト専用のローカルサービスをすぐに待ち受け状態にして、ゲーム表示領域が既定 `1920 × 1080` となる専用Edgeウィンドウを開きます。タイトルバーと枠は表示領域の外側にあるため、実際のウィンドウは少し大きくなります。復旧処理と初回スキャンはゲーム内のロード画面で完了するため、時間のかかる初回スキャンがポート競合として誤表示されません。再起動時は、このコピーが前回起動したサービスと専用Edgeゲームウィンドウだけを置き換えます。

`terminate.cmd` をダブルクリックすると、このプロジェクトのサービスと、プロジェクトが起動した専用Edgeゲームウィンドウを閉じられます。プロジェクトの場所、ランダムなセッショントークン、専用ブラウザー記録を照合するため、別のアプリが使用している `node.exe` や通常のブラウザープロセスは終了しません。

`index.html` を直接開かないでください。ブラウザーのローカルファイル制限により必要な処理がブロックされるため、ランチャー、Web サーバー、または静的デプロイ先を使用してください。

### 開発環境とその他の OS

同梱の Windows x64 ランタイムを使用しない場合は、Node.js 20 以降が必要です。

```sh
npm ci
npm run start-local -- --open
```

## 主な機能

- 初回にブラウザー言語を判定する中国語・英語・日本語 UI。
- 英字、声調記号なしの中国語ピンイン、複数綴り対応の日本語ローマ字。
- 入力対象は英字だけ。スペースと句読点は歌詞に表示されますが、判定には含まれません。
- オフにできる先読み Keyfall と、軽量な連続正解エフェクト。
- 初期状態でオフのMV。取り込み元、地域、回線状態に応じてサービス側の記録、Bilibili、YouTube、Niconicoなどを並べ替え、同じ音源・時刻を検証したMVを優先します。採用した映像は永続キャッシュし、次回から再ダウンロードしません。見つからない場合は直接タイアップ作品と確認できた公式OP・ED・PV映像を無音ループで使用します。現在の曲に利用可能なキャッシュがなく、検索または読み込みに失敗した場合はMV設定を自動でオフにし、次の曲で同じ検索を繰り返しません。
- 人に近いリズムのパーフェクトオートデモ。
- 選曲、デモ、リザルトで統一された必要キー数/分。
- スコアカード、入力安定度、時間ごとのペースグラフ。
- キーボード、マウス、ホイール操作。
- 階層コレクションのソート、複数曲削除、ワンクリックリセット。
- チェックサム検証済みのスターター曲3曲。
- QQ Music、NetEase Cloud Music、Apple Music、ローカルフォルダーの取り込み機能を同梱。
- インスト、BGM、歌詞なしメッセージ、クレジット行を自動除外し、間奏を含んだ異常に長い歌詞入力時間を補正。
- ローカル音声・動画と、対応する YouTube `.typingmania` パッケージ。

## スターターライブラリ

3種類の歌詞処理を検証するため、固定の追加日時で次のスターター曲を収録しています。

1. 中国語：`指尖星光`
2. 英語：`Letters in the Light`
3. 日本語：`明日へのリズム`

収録した音源、歌詞、SVG アートはネットワークアクセスや音楽サービスのデータを使用しません。ローカルサーバーは起動のたびに `.typingmania` をスキャンし、非公開キャッシュとツール用ディレクトリを除外して重複のない `data/songs.json` を作成します。

## 音楽サービスから曲を追加

メイン画面の「曲を追加」から、QQ Music、NetEase Cloud Music、Apple Music、ローカルフォルダーのいずれかを選びます。変換ツールと言語処理ライブラリはすべて同梱済みで、取り込み時のインストールやツールのダウンロードはありません。共通の採用条件は[取り込みガイド](docs/importing-music.md)にまとめています。

### QQ Music

取り込みには Windows と、起動してログイン済みの QQ Music デスクトップアプリが必要です。`QQMusicCache` と一般的なダウンロード先を同時に調べ、MFLAC・MGG・QRC キャッシュは曲単位で厳密に検証します。通常の MP3、FLAC、M4A、AAC、MP4、OGG、WAV ダウンロードは、タグ・長さ・歌詞・QQ Music カタログが一致した場合だけ採用します。

各バッチでは次の処理を自動で行います。

1. プロジェクト、ドライブ直下、QQ Music プロセス情報、一般的な保存先、設定からキャッシュとダウンロード先を探します。
2. 現在のセッションは取り込み中だけ読み取ります。
3. 最近の異なる候補を選び、取り込み済みの曲を除外します。
4. 曲名、アーティストまたはサウンドトラック名、長さ、歌詞本文、Roma の時刻を照合します。
5. 曲名、アーティスト、作詞、作曲、編曲、プロデューサーなどの非歌詞行を言語別に除去します。
6. 利用できる場合は、完全な時刻付き歌詞を公式レスポンスと照合します。
7. 中国語は声調記号なしピンインをローカル生成し、日本語は全行を含む同一曲固有の `_qmRoma.qrc` を必須とします。
8. オンライン時は QQ Music の Roma レスポンスも照合します。オフライン時は曲の同一性、長さ、カラオケ時刻を厳密に確認できた読みだけを採用し、不確かな読みを推測しません。
9. QMC2 音声をメモリー上で復号し、実際の FLAC／OGG コンテナと全再生時間を検証します。ログイン中のアカウントで利用できない会員曲は曲単位で飛ばし、利用可能な無料曲の取り込みを続けます。
10. アーティスト原名と、その曲を直接使用した作品を確認します。
11. 検証済みアルバム画像と、確実に一致する場合は作品ポスターを選びます。
12. 自己完結した非公開曲パッケージをアトミックに保存します。

取り込み前に1～500曲（初期値10曲）を指定できます。`Esc` または `Backspace` で安全に停止でき、完了した曲は残り、直近5件の失敗理由も表示されます。利用できない候補はその枠に数えません。もう一度実行すると、次の異なる曲から続行します。詳しくは
[ローカル QQ Music ライブラリ](docs/local-qqmusic.md)と
[QQ Music 相互運用に関する注意](QQMUSIC-INTEROPERABILITY-NOTICE.md)をご覧ください。

### NetEase Cloud Music

Windows アプリを起動してログインします。TypingManiaNovel は完全な `.ncm`、通常の MP3/FLAC/M4A/AAC/MP4/OGG/WAV ダウンロード、クライアント世代ごとの `.uc`/`.uc!` キャッシュを探します。NCM は同梱 ncmdump で変換し、通常ファイルはタグ・カタログ・長さを照合します。キャッシュは復号後、ヘッダー・曲 ID・再生時間に加え、サービス側が公開する完全ファイルのバイト数まで一致したときだけ採用します。1～500曲から選んだ目標に候補が届かなくても、見つかった分で正常に完了します。日本語漢字には同じ曲の時刻付き `romalrc` が必要です。詳しくは[ローカル NetEase ガイド](docs/local-netease.md)をご覧ください。

### Apple Music

Windows アプリを起動・ログインし、Edge・Chrome・Firefox のいずれかで `music.apple.com` にもログインします。Apple ドメインのセッション情報だけを一時領域へ自動抽出し、読み取れない場合のみ非公開 Cookie ファイルを案内します。1～500曲から目標を指定して曲・アルバム・プレイリストの URL を貼り付けると、既存の Apple 曲 ID を先に除外し、転送前に選択数で止めてから、同梱の Python/gamdl がそのアカウントで再生可能な曲の AAC 256 M4A と同期 LRC を生成します。再実行すると後続曲へ進みます。その後も他の取り込み元と同じく、暗号化状態、音声構造、長さ、歌詞、読み、作品原題、画像、重複を検証します。日本語漢字は同じ録音の Roma 時刻軸と照合できた場合だけ採用します。詳しくは[ローカル Apple Music ガイド](docs/local-apple-music.md)をご覧ください。

### ローカルフォルダー

フォルダーを選ぶと、対応音声、同名 LRC、画像をサブフォルダーまで検索し、localhost の非公開一時領域へコピーして検証します。埋め込みタグと画像を優先し、地域別に選ばれた歌詞ソースで同名 LRC の本文を照合します。別の曲だと判断できる場合は厳密一致した配信元の時刻軸へ切り替え、ネットワークが使えない場合は基本検証済みのローカル歌詞へフォールバックします。中国語ピンインはローカル生成、日本語漢字は同じ録音の時刻付き読みが必須です。元ファイルは移動・変更せず、一時コピーは検証後すぐ削除します。

全取り込み方式に共通する境界は[音楽サービス相互運用に関する注意](MUSIC-SERVICE-INTEROPERABILITY-NOTICE.md)に記載しています。

## 歌詞・読み・画像の取得元

- 日本語の読みは、同じ曲の時刻付き QQ Music Roma QRC、NetEase `romalrc`、または一致を確認した KuGou KRC のローマ字層を使用します。そのため、表記とは異なる作詞者指定の歌い方もそのまま入力に反映できます。
  [TypingMania NEO](https://github.com/innocenat/typingmania) 由来の
  `latin-table/` は通常パッケージの仮名入力に使用し、取り込み曲固有の読みを推測したり上書きしたりしません。
- 中国語ピンインは [`pinyin-pro`](https://github.com/zh-lx/pinyin-pro) でローカル生成します。
- ユーザーが取り込みを開始したとき、選択したサービスから利用権のあるメディア、曲情報、公式時刻付き歌詞、アルバム画像を取得します。QQ Music、NetEase、KuGou、[LRCLIB](https://www.lrclib.net/) の厳密一致ルートは、地域別の初期順位、実際の成功、失敗時のクールダウン、応答速度で並び替えます。
- 曲名、正式なアーティスト表記、リリース、アルバムは [Apple iTunes Search](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/)、[MusicBrainz](https://musicbrainz.org/doc/MusicBrainz_API)、[Cover Art Archive](https://musicbrainz.org/doc/Cover_Art_Archive/API) でも照合します。既存の曲名やアーティストを直すのは、厳密一致または独立した2カタログが高い確度で同じ修正を示した場合だけです。
- [AniSongDB](https://anisongdb.com/) と [AnimeThemes](https://animethemes.moe/) は曲を直接使用したアニメ作品候補を曲単位で提示し、[AniList](https://anilist.co/) と [Bangumi](https://bangumi.github.io/api/) が作品ID、原語タイトル、ポスターを相互確認します。映画とドラマは Bangumi、[TVmaze](https://www.tvmaze.com/api)、任意設定の [TMDB](https://developer.themoviedb.org/reference/search-movie) でも確認します。漫画、小説など改編前の原作を直接出典として置き換えません。
- [YouTube IFrame API](https://developers.google.com/youtube/iframe_api_reference) は対応する YouTube 曲パッケージだけで使用します。

曲名の翻訳機能はありません。保存された原題だけを表示します。作品名も、楽曲を直接使用した作品の原題を確認できた場合だけ表示し、不確かな場合は空欄にします。

ゲーム内の「このゲームについて」から主要コンポーネントと情報源を開けます。ライセンスの一覧は
[サードパーティー表示](THIRD-PARTY-NOTICES.md)にあります。

## ペースとリザルト

選曲画面のペース表示は次の意味です。

- **曲全体の平均**：プレイ可能な時間軸全体で1分あたりに必要な英字キー数。
- **最速5秒**：連続する任意の5秒間で最も高い英字キー入力レート。

選曲、オートデモ、リザルトは同じ文字数、歌詞時刻、集計窓を使います。最初の歌詞が1.5秒より前に始まる曲では短い 3–2–1 カウントを表示しますが、メディア時刻はずらしません。通常クリア時はプレイ画面を1.4秒残してからリザルトへ移ります。

## 曲の編集とリセット

「曲を編集」はキーボードとマウスで複数選択できます。確定後は対象パッケージを一時退避し、索引を再構築して、その曲のスコアと参照されなくなった非公開メタデータだけを削除します。確定前に中断した処理は次回起動時にロールバックされます。スターター3曲は個別削除できません。

「ライブラリをリセット」は最初に対象を選びます。全取り込み曲を消してスターター3曲へ戻すことも、QQ Music、NetEase Cloud Music、Apple Music、ローカルフォルダーの1種類だけを消すこともできます。対応するスコアと未参照メタデータだけを削除し、音楽アプリのキャッシュ・ダウンロード先・選択した元フォルダー・Cookie ストアは変更しません。

「曲情報を更新」は取り込み済みの全曲を再確認します。取り込み元で検証できる曲情報を取得し、独立した音楽カタログで曲名の綴り、正式なアーティスト表記、リリース、歌詞言語を照合します。修正には厳密一致または独立2ソースの高信頼な合意が必要です。アニメ・映画・ドラマ・ドキュメンタリー・CM・バラエティ・スポーツ・ビジュアルノベル・JRPG・ゲームの直接出典、作品原題、ポスターは対応する作品カタログで検証します。既存の確かな情報と競合する内容は上書きせず、新しい不確かな項目は空欄にします。`Esc` または `Backspace` を押すと、接続先のタイムアウトを待たずに現在の通信処理を直ちに中断します。すでにアトミック保存された確認済みの更新は残ります。

## ネットワークとデプロイ

通常の起動、メニュー、スターター曲、取り込み済みローカル曲、読み、スコア、オートデモ、Keyfall、リザルトはローカルで動作します。ネットワークを使うのは、ユーザーが開始した取り込み、任意の情報・画像更新、MVをオンにして未キャッシュ曲を初めて開いた場合、または YouTube 曲を選択した場合だけです。

IP による位置特定は行いません。システム言語・タイムゾーン、または任意の `TMN_NETWORK_REGION`（`cn`、`hk`、`tw`、`jp`、`kr`、`sea`、`us`、`eu`、`global`）から初期順位を選び、その後は実際の成功・失敗・遅延で並び替えます。中国本土では QQ Music、NetEase、KuGou、Bangumi を先にし、香港/マカオ、台湾、日本、韓国、東南アジア、米国、欧州、その他の地域では到達可能な LRCLIB、iTunes Search、MusicBrainz、TVmaze、TMDB、Wikidata の順位を適宜上げます。作品情報はサービス/公式記録、専門データベース、百科の相互確認、公式メディアの順で優先し、メディアプラットフォームの結果だけでは確定しません。各経路には短いタイムアウト、有限の再試行、失敗時のクールダウン、バッチ単位のサーキットブレーカーがあります。確認できない任意項目は空欄または同梱のニュートラル画像にし、プレイ可能な歌詞または必要な読みを確認できない曲だけを除外します。

### 静的ホスティング

```sh
npm run build-game
```

`dist/` を GitHub Pages などに配置すると、ビルドに含まれる曲をプレイできます。

音楽サービスからの取り込み、起動時ファイルスキャン、トランザクション付き削除/リセット、パッケージ内画像の展開にはローカルサーバーが必要で、静的サイトでは利用できません。非公開の `data/` を公開ビルドへ含めないでください。

## プライバシー

ローカルサーバーは `127.0.0.1` だけで待ち受けます。データを変更する API にはランダムな同一オリジントークンが必要です。QQ Music のセッション、NetEase の元ファイル、Apple Music の Cookie は、ユーザーが開始したローカル取り込みだけで使用し、公開パッケージ、ログ、Release には保存しません。

Git では次のファイルを除外します。

- すべての `QQMusicCache`
- NetEase の `.ncm`/`.uc`、Apple Music Cookie、フォルダー取り込みの一時コピー、各クライアントのキャッシュ
- `data/` 以下の生成データ
- 取り込んだ音源、歌詞、カバー、ポスター、セッション、ログ、PID
- ローカル参照画像と環境変数ファイル

公開前の確認：

```sh
npm run audit-public
```

追跡済みおよび公開候補の未追跡ファイルを走査し、非公開メディア、スターター以外の曲パッケージ、ユーザープロファイルのパス、実行状態、一般的な認証情報の形式を検出します。

## Song Studio

ローカルサーバーを起動し、次を開きます。

```text
http://127.0.0.1:8765/preview.html
```

`packer.html` は互換用入口です。Preact と HTM は `vendor/editor` に同梱され、公開 CDN に依存しません。YouTube プレビューには YouTube 接続が必要ですが、ローカル音声・動画には不要です。

## 検証

```sh
npm test
npm run build-game
npm run audit-library
npm run verify-runtime
npm run audit-public
```

`audit-library` は公開パッケージに含まれる3曲のサンプルだけを検査します。このPCの非公開ライブラリ全体を検査する場合は `npm run audit-local-library` を実行してください。非公開曲がリリースへ追加されることはありません。

すべてまとめて実行：

```sh
npm run check
```

Jest は単一プロセスで実行するため、Windows にワーカープールの `node.exe` を残しません。
