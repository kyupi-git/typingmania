# TypingManiaNovel

[简体中文](README.md) | [English](README.en.md) | **日本語**

**バージョン：20260719**

TypingManiaNovel は
[TypingMania NEO](https://github.com/innocenat/typingmania)
をベースに再開発した、多言語対応の歌詞タイピング音楽ゲームです。中国語・英語・日本語の楽曲、ローカル実行と静的サイトでのプレイ、Keyfall、オートデモ、ライブラリ管理、Windows 版 QQ Music からの取り込みに対応しています。

> **QQ Music の曲をそのまま追加できます：** QQ Music を起動してログインしておけば、キャッシュ音源の復号、歌詞と読みの検証、画像の取得、プレイ可能な曲への変換をゲームが自動で行います。

[`TypingManiaNovel-20260719-Windows-x64.zip`](https://github.com/kyupi-git/typingmania/releases/download/v20260719/TypingManiaNovel-20260719-Windows-x64.zip)
をダウンロードし、展開して
`start-game.cmd` をダブルクリックしてください。実行環境とスターター曲3曲が同梱されているため、Node.js や npm のインストールは不要です。

公開リポジトリに含まれる楽曲は、プロジェクト独自制作の中国語・英語・日本語のスターター曲各1曲だけです。QQ Music のキャッシュ、取り込んだメディア、アカウントセッション、再生履歴、個人ライブラリは含まれません。

## すぐに遊ぶ

### Windows 11 x64

1. Release の ZIP をダウンロードして展開するか、リポジトリ全体をクローンします。
2. `start-game.cmd` をダブルクリックします。
3. Edge またはモダンブラウザーでプレイします。

初回起動時は、同梱の Node.js ランタイムを検証して展開し、このプロジェクト専用のローカルサービスを1つ起動します。ライブラリのスキャン完了後にゲームが開き、2回目以降は同じサービスを再利用します。

`terminate.cmd` をダブルクリックすると、このプロジェクトのサービスだけを停止できます。プロジェクトの場所とランダムなセッショントークンを照合するため、別のアプリが使用している `node.exe` は終了しません。

`index.html` を直接開かないでください。ブラウザーのローカルファイル制限により必要な処理がブロックされるため、ランチャー、Web サーバー、または静的デプロイ先を使用してください。

### 開発環境とその他の OS

同梱の Windows x64 ランタイムを使用しない場合は、Node.js 20 以降が必要です。

```sh
npm ci
npm run start-local -- --open
```

## TypingMania NEO fork との違い

比較対象は、TypingMania NEO の基準として公開されている
[`kyupi-git/typingmania` fork の `82c75d7`](https://github.com/kyupi-git/typingmania/tree/82c75d77396025e1a73c1e710c32e8716f83c734)
です。

| 項目 | TypingMania NEO fork 基準 | TypingManiaNovel |
| --- | --- | --- |
| 製品名 | TypingMania NEO 1.1.1 | TypingManiaNovel |
| 起動 | Web サーバーを手動で起動、またはサイトへ配置 | ランタイム同梱のワンクリック起動、単一サービスの再利用と安全な停止。静的配置にも対応 |
| UI | 主に英語、キーボード中心 | ブラウザー言語の自動判定、中国語・英語・日本語 UI、言語選択、クリックとホイール操作 |
| ライブラリ | 静的インデックス、URL、`.typingmania` のドラッグ＆ドロップ | 起動時スキャン、重複排除、階層コレクション、画像プレビュー、追加日・必要キー数/分・曲名・アーティストの昇順/降順ソート |
| 取り込み | ユーザーが曲パッケージを用意 | QQ Music キャッシュから毎回次の20曲を選び、セッション確認、復号、検証、重複排除を自動実行 |
| 歌詞 | 日本語漢字の読みを含め手作業が中心 | 中英日別にクレジット行を除去。QQ 取り込み時は中国語ピンインを生成し、日本語は曲固有の時刻付き Roma QRC を使用 |
| 入力 | スペースや変換済みの記号が入力対象になる場合がある | 歌詞にはスペースや記号を残し、プレイでは英字キーだけを入力 |
| 日本語入力 | 仮名・ローマ字表と複数入力パターン | 元の複数入力モデルを維持し、取り込んだ曲固有の読みを区切り文字なしに正規化 |
| 画像と出典 | 曲パッケージごとに1枚 | 確認できた場合は楽曲を直接使用した作品のポスターを背景にし、アルバム画像を別表示。根拠が弱い出典は表示しない |
| 速度指標 | 90パーセンタイルと最大 CPM | 全曲平均と最速5秒の必要キー数/分。オートデモとリザルトも同じ計算方法 |
| 自動プレイ | 隠し Auto モード。プレイヤー入力の影響を受ける場合がある | 人に近い間隔でパーフェクト演奏を見せる明示的なオートデモ。スコアは保存しない |
| フィードバック | 基本効果音とゲームモード | 先読み Keyfall、正解・ミス・見逃し表示、連続正解の光と節目の効果音。オン/オフ可能 |
| リザルト | スコア、ランク、コンボ、正確率、行数 | 詳細スコアカード、入力の安定度、時間別ペースグラフ、基準ペース、最終行後の自然な間 |
| ライブラリ管理 | 複数選択編集とクリーンリセットなし | ロールバック可能な複数曲削除と、検証済みスターター3曲へのリセット |
| ネットワーク | 対応曲の YouTube 再生 | 通常プレイはローカル優先。QQ Music と Bangumi の補完処理は短いタイムアウト、地域別代替先、サーキットブレーカーを使用 |
| Song Studio | 開発中のビジュアルエディター | Preact/HTM をローカル同梱し、公開 CDN に依存しない Song Studio |
| 検証 | 元の Jest とビルドスクリプト | 単体テスト、曲品質、ランタイム整合性、公開ファイル、静的ビルド、ブラウザースモークテスト |

元の `.typingmania` 形式との互換性を可能な限り保ち、ローカル音声・動画と YouTube 対応曲を利用できます。

## 主な機能

- 初回にブラウザー言語を判定する中国語・英語・日本語 UI。
- 英字、声調記号なしの中国語ピンイン、複数綴り対応の日本語ローマ字。
- 入力対象は英字だけ。スペースと句読点は歌詞に表示されますが、判定には含まれません。
- オフにできる先読み Keyfall と、軽量な連続正解エフェクト。
- 人に近いリズムのパーフェクトオートデモ。
- 選曲、デモ、リザルトで統一された必要キー数/分。
- スコアカード、入力安定度、時間ごとのペースグラフ。
- キーボード、マウス、ホイール操作。
- 階層コレクションのソート、複数曲削除、ワンクリックリセット。
- チェックサム検証済みのスターター曲3曲。
- ローカル音声・動画と、対応する YouTube `.typingmania` パッケージ。

## スターターライブラリ

3種類の歌詞処理を検証するため、固定の追加日時で次のオリジナル曲を収録しています。

1. 中国語：`指尖星光`
2. 英語：`Letters in the Light`
3. 日本語：`明日へのリズム`

音源、歌詞、SVG アートはプロジェクト独自の素材で、ネットワークアクセスや音楽サービスのデータを使用しません。ローカルサーバーは起動のたびに `.typingmania` をスキャンし、非公開キャッシュとツール用ディレクトリを除外して重複のない `data/songs.json` を作成します。

## QQ Music から曲を追加

メイン画面の「曲を追加」から「QQ Music」を選びます。「その他の方法」は将来の拡張用で、現在は利用できません。

取り込みには Windows、起動してログイン済みの QQ Music デスクトップアプリ、完全にキャッシュされた音声と QRC が必要です。アプリが起動していない、ログインしていない、またはセッションを利用できない場合は、選択中の UI 言語で原因を案内します。

各バッチでは次の処理を自動で行います。

1. プロジェクト、ドライブ直下、QQ Music プロセス情報、一般的な保存先、設定から `QQMusicCache` を探します。
2. 現在のセッションは取り込み中だけ読み取ります。
3. 最近の異なる候補を選び、取り込み済みの曲を除外します。
4. 曲名、アーティストまたはサウンドトラック名、長さ、歌詞本文、Roma の時刻を照合します。
5. 曲名、アーティスト、作詞、作曲、編曲、プロデューサーなどの非歌詞行を言語別に除去します。
6. 利用できる場合は、完全な時刻付き歌詞を公式レスポンスと照合します。
7. 中国語は声調記号なしピンインをローカル生成し、日本語は全行を含む同一曲固有の `_qmRoma.qrc` を必須とします。
8. オンライン時は QQ Music の Roma レスポンスも照合します。オフライン時は曲の同一性、長さ、カラオケ時刻を厳密に確認できた読みだけを採用し、不確かな読みを推測しません。
9. QMC2 音声をメモリー上で復号し、FLAC を検証します。
10. アーティスト原名と、その曲を直接使用した作品を確認します。
11. 検証済みアルバム画像と、確実に一致する場合は作品ポスターを選びます。
12. 自己完結した非公開曲パッケージをアトミックに保存します。

利用できない候補は20曲の枠に数えません。もう一度実行すると、次の異なる曲から続行します。詳しくは
[ローカル QQ Music ライブラリ](docs/local-qqmusic.md)と
[QQ Music 相互運用に関する注意](QQMUSIC-INTEROPERABILITY-NOTICE.md)をご覧ください。

## 歌詞・読み・画像の取得元

- 日本語の読みは、同じ曲の時刻付き QQ Music Roma QRC を使用します。そのため、表記とは異なる作詞者指定の歌い方もそのまま入力に反映されます。
  [TypingMania NEO](https://github.com/innocenat/typingmania) 由来の
  `latin-table/` は通常パッケージの仮名入力に使用し、取り込み曲固有の読みを推測したり上書きしたりしません。
- 中国語ピンインは [`pinyin-pro`](https://github.com/zh-lx/pinyin-pro) でローカル生成します。
- ユーザーが取り込みを開始したとき、QQ Music から利用可能な曲情報、公式時刻付き歌詞、アーティスト情報、アルバム画像を取得します。
- [Bangumi](https://bangumi.github.io/api/) は、アニメ関連曲を直接使用した作品の原題とポスターの確認に使用します。漫画、小説、別の原作作品をアニメの直接出典として置き換えません。
- [YouTube IFrame API](https://developers.google.com/youtube/iframe_api_reference) は対応する YouTube 曲パッケージだけで使用します。

曲名の翻訳機能はありません。保存された原題だけを表示します。作品名も、楽曲を直接使用した作品の原題を確認できた場合だけ表示し、不確かな場合は空欄にします。

ゲーム内の「このゲームについて」から主要コンポーネントと情報源を開けます。ライセンスの一覧は
[サードパーティー表示](THIRD-PARTY-NOTICES.md)にあります。

## ペースとリザルト

選曲画面のペース表示は次の意味です。

- **曲全体の平均**：プレイ可能な時間軸全体で1分あたりに必要な英字キー数。
- **最速5秒**：連続する任意の5秒間で最も高い英字キー入力レート。

選曲、オートデモ、リザルトは同じ文字数、歌詞時刻、集計窓を使います。最初の歌詞が1.5秒より前に始まる曲では短い 3–2–1 カウントを表示しますが、メディア時刻はずらしません。通常クリア時はプレイ画面を1.4秒残してからリザルトへ移ります。

## 曲の編集とリセット

「曲を編集」はキーボードとマウスで複数選択できます。確定後は対象パッケージを一時退避し、索引を再構築して、その曲のスコアと参照されなくなった非公開メタデータだけを削除します。確定前に中断した処理は次回起動時にロールバックされます。スターター3曲は個別削除できません。

「ライブラリをリセット」は、追加曲、生成済みメタデータキャッシュ、保存スコアを削除し、検証済みスターター3曲へ戻します。どちらの操作も `QQMusicCache` という名前のディレクトリを変更しません。

## ネットワークとデプロイ

通常の起動、メニュー、スターター曲、取り込み済みローカル曲、読み、スコア、オートデモ、Keyfall、リザルトはローカルで動作します。ネットワークを使うのは、ユーザーが開始した取り込み、任意の情報・画像更新、または YouTube 曲を選択した場合だけです。

QQ Music は中国本土向けのサービスエンドポイントを利用します。作品名とポスターの任意検索は Bangumi 公式の `bgm.tv`、`bangumi.tv`、`chii.in` と API の間で短いリクエスト予算を共有します。再試行は有限で、連続失敗するとそのバッチの任意通信を停止し、検証可能なローカル情報を使うか空欄にします。通常プレイを待たせません。

### 静的ホスティング

```sh
npm run build-game
```

`dist/` を GitHub Pages などに配置すると、ビルドに含まれる曲をプレイできます。

QQ Music 取り込み、起動時ファイルスキャン、トランザクション付き削除/リセット、パッケージ内画像の展開にはローカルサーバーが必要で、静的サイトでは利用できません。非公開の `data/` を公開ビルドへ含めないでください。

## プライバシー

ローカルサーバーは `127.0.0.1` だけで待ち受けます。データを変更する API にはランダムな同一オリジントークンが必要です。QQ Music の Cookie、アカウント識別子、ekey は実行中のメモリーだけで扱い、記録・保存しません。

Git では次のファイルを除外します。

- すべての `QQMusicCache`
- `data/` 以下の生成データ
- 取り込んだ音源、歌詞、カバー、ポスター、セッション、ログ、PID
- ローカル参照画像と環境変数ファイル

公開前の確認：

```sh
npm run audit-public
```

追跡済みおよび公開候補の未追跡ファイルを走査し、非公開メディア、スターター以外の曲パッケージ、ユーザープロファイルのパス、実行状態、一般的な認証情報の形式を検出します。

## Song Studio

ローカルサーバーを起動し、次を開きます。

```text
http://127.0.0.1:8765/preview.html
```

`packer.html` は互換用入口です。Preact と HTM は `vendor/editor` に同梱され、公開 CDN に依存しません。YouTube プレビューには YouTube 接続が必要ですが、ローカル音声・動画には不要です。

## ディレクトリ構成

```text
assets/              フォント、UI 画像、効果音のソースとパック
docs/                ユーザー向け・相互運用ドキュメント
latin-table/         文字正規化と日本語ローマ字表
scripts/             ビルド、監査、ローカルサーバー、起動補助、取り込み
scripts/local/       ローカルライブラリのモジュールとテスト
songs/               公開スターター曲3曲
src/                 ゲーム、UI、メディア、タイピング、エフェクト、エディター
tools/runtime/       検証済み Windows Node.js ランタイム ZIP とライセンス
vendor/editor/       Song Studio のローカルブラウザー依存とライセンス
vendor/runtime/      バージョン固定のオフライン取り込み依存とライセンス
```

生成したビルド、開発用依存、ブラウザー自動化状態、ランタイム展開先、非公開ライブラリはバージョン管理されません。

## 検証

```sh
npm test
npm run build-game
npm run audit-library
npm run verify-runtime
npm run audit-public
```

すべてまとめて実行：

```sh
npm run check
```
