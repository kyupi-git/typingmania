# TypingManiaNovel

**简体中文** | [English](README.en.md) | [日本語](README.ja.md)

**当前版本：20260726**

[更新记录](CHANGELOG.md) · [20260726 发行说明](docs/releases/20260726.md)

TypingManiaNovel 是一款基于
[TypingMania NEO](https://github.com/innocenat/typingmania)
二次开发的多语言歌词打字音游。它支持中、英、日三语歌曲，可在本机或静态网站运行，并提供按键雨、自动演示、曲库管理，以及 QQ 音乐、网易云音乐、Apple Music 和本地文件夹导入功能。

> **可以直接导入并自动生成可玩曲目：** 支持 QQ 音乐缓存与下载、网易云音乐下载与完整缓存、已登录 Apple Music 账号能够访问的歌曲/专辑/歌单链接，以及用户选择的本地文件夹。游戏会自动转换音频、核对歌词与发音、匹配图片，并生成可离线游玩的曲目；受账号权限限制的单曲仍需该账号具有相应播放权限。

## 快速开始

### Windows x64

1. 下载并解压 Release 压缩包，或克隆完整项目。
2. 双击 `start-game.cmd`。
3. 在 Edge 或其它现代浏览器中开始游玩。

免安装的一键启动暂时只支持 Windows x64；其它平台仍可按下一节安装 Node.js 后运行。

启动器首次运行时会校验并解压内置 Node.js 运行环境，再立即绑定本机端口并以默认 `1920 × 1080` 的游戏画面打开专用 Edge 窗口；标题栏和边框位于画面之外，因此实际窗口会略大。曲库恢复与首次扫描在游戏加载页内完成，不会再把较慢的首次扫描误报为“端口被占用”。再次启动只会替换本项目上一次的服务与专用 Edge 游戏窗口。

双击 `terminate.cmd` 可立即停止此项目的后台服务，并关闭由本项目启动的专用 Edge 游戏窗口。终止程序会核对当前目录、随机会话令牌和专用浏览器记录，不会结束其它软件使用的 `node.exe` 或普通浏览器进程。

不要直接双击 `index.html`。浏览器对本地文件的安全限制会拦截游戏所需功能，请使用启动器、Web 服务器或静态部署地址。

### 开发环境与其它平台

未使用内置 Windows x64 运行环境时，需要 Node.js 20 或更新版本：

```sh
npm ci
npm run start-local -- --open
```

## 主要功能

- 中、英、日三语界面，首次打开时自动匹配浏览器语言。
- 英语字母、无声调汉语拼音和支持多种拼法的日语罗马字输入。
- 只输入字母；空格和标点保留在歌词中，但不参与判定。
- 可关闭的预测式按键雨与低负载连击反馈。
- 默认关闭的 MV：优先按导入服务、所在地区和线路状态从服务端记录、Bilibili、YouTube、Niconico 等来源检索。录音与时间轴验证通过的同版本 MV 会持久缓存并在以后直接复用；若没有，再使用已核实为直接出处作品的官方片头、片尾或宣传影像并循环播放。当前歌曲没有可用缓存且检索或加载失败时会自动关闭 MV，避免进入后续歌曲时反复检索；作品海报与专辑封面仍可正常显示。
- 以接近真人节奏进行完美游玩的自动演示。
- 曲目选择、演示与结算页面使用一致的每分钟按键数口径。
- 成绩卡、键入流畅度分析和随时间变化的速度图。
- 键盘、鼠标和滚轮操作。
- 支持二级曲库排序、多选删除和一键重置。
- 三首校验和固定的示例歌曲。
- QQ 音乐、网易云音乐、Apple Music 与本地文件夹导入，所需转换组件均已随游戏提供。
- 自动剔除伴奏、BGM、占位歌词及非歌词信息，并修正明显包含间奏的异常长歌词时间窗。
- 支持本地音视频及兼容的 YouTube `.typingmania` 歌曲包。

2. 英语：`Letters in the Light`

## 从音乐服务添加歌曲

在主界面打开“添加歌曲”，可选择“QQ 音乐”“网易云音乐”“Apple Music”或“本地文件夹”。转换程序和语言处理组件均已保存在项目中，玩家无需在导入时安装或下载工具。各导入方式的前置条件和数据路径见[音乐导入总览](docs/importing-music.md)。

### QQ 音乐

QQ 音乐导入需要 Windows 以及正在运行且已登录的 QQ 音乐桌面客户端。程序会同时检查 `QQMusicCache` 和常用下载目录：缓存中的 MFLAC、MGG 与 QRC 走逐曲严格校验，下载目录中的普通 MP3、FLAC、M4A、AAC、MP4、OGG 或 WAV 也会按标签、时长和 QQ 音乐在线目录严格匹配后导入。

每批导入会自动完成：

1. 从项目目录、分区根目录、QQ 音乐进程信息、常用目录和配置中定位缓存与下载目录。
2. 只在本次导入期间读取当前会话。
3. 按最近使用顺序选择不同缓存，并与已有歌曲去重。
4. 结合标题、歌手或原声专辑、时长、歌词正文与 Roma 时间轴匹配 QRC。
5. 按语言过滤歌曲名、歌手、作词、作曲、编曲、制作人等非歌词行。
6. 网络可用时与官方歌词响应核对完整时间轴。
7. 本地生成无声调中文拼音；日语要求每句都有同一歌曲专属 `_qmRoma.qrc` 读音。
8. 网络可用时交叉核对 QQ 音乐 Roma 响应；离线时只接受身份、时长和卡拉 OK 时间均能严格证明的本地读音，无法确认则跳过而不猜测。
9. 在内存中解密 QMC2 音频，识别 FLAC、OGG 等实际容器，并核对完整时长；无权访问的会员曲目会逐曲跳过，不影响免费歌曲继续导入。
10. 解析歌手原名和真正直接使用这首歌的作品。
11. 选择经过验证的专辑封面，并尽可能匹配直接出处作品的海报。
12. 以原子方式写入一个自包含的私有歌曲包。

导入前可指定本批希望新增的曲数（1～500，默认10首）。按 `Esc` 或 `Backspace` 可在安全节点停止，已完成曲目会保留，并列出最近5个失败候选的阶段和原因。不可用候选不会占用名额；再次执行导入会继续寻找后面的不同歌曲。

更多细节见 [本地 QQ 音乐曲库](docs/local-qqmusic.md)和
[QQ 音乐互操作声明](QQMUSIC-INTEROPERABILITY-NOTICE.md)。

### 网易云音乐

保持 Windows 版网易云音乐已启动并登录。游戏会同时发现完整 `.ncm`、未加密的 MP3/FLAC/M4A/AAC/MP4/OGG/WAV 下载，以及不同客户端版本使用的 `.uc`/`.uc!` 缓存。NCM 使用内置 ncmdump 转换；普通下载必须通过标签、曲目目录与时长匹配；缓存会先异或解码，再核对文件头、曲目 ID、可播放时长和服务端公布的完整文件字节数。无法证明完整的缓存不会进入曲库。玩家可为每批指定 1～500 首；候选不足时正常返回已找到的数量，再次导入会继续跳过已有记录。

日语歌词含汉字时，必须取得属于同一曲目的时间轴 `romalrc`；无法确认实际唱法时会跳过，不会用词典读音猜测。详细逻辑见[本地网易云音乐曲库](docs/local-netease.md)。

### Apple Music

保持 Windows 版 Apple Music 已启动并登录；同时在 Edge、Chrome 或 Firefox 登录 `music.apple.com`。程序会优先临时提取仅限 Apple 域的会话信息，无法自动读取时才提示使用私有 Cookie 文件。选择导入后指定 1～500 首并粘贴歌曲、专辑或歌单链接，内置 Python/gamdl 运行环境会跳过已有 Apple 曲目，在实际传输前按本批目标停止，再为当前账号能够播放的曲目生成 AAC 256 M4A 和同步 LRC。输出仍会经过解密状态、音频结构、时长、歌词、读音、封面和重复项校验；再次导入会继续处理后续曲目。

Apple Music 的同步歌词并非总能提供日语特殊读音；含汉字的歌曲只有在能够与同一录音的逐曲 Roma 时间轴交叉确认时才会加入。配置位置与隐私边界见[本地 Apple Music 曲库](docs/local-apple-music.md)。

### 本地文件夹

选择任意文件夹后，浏览器会递归提交其中受支持的音频、同名 LRC 和封面图片给仅监听本机的服务。程序优先使用音频内嵌标签与图片，并用地区优选的歌词源核对同名 LRC；若文本明显属于另一首歌，则改用已严格匹配曲目的在线时间轴，断网时仍可降级使用通过基础校验的本地歌词。中文生成拼音，日语汉字必须取得同一录音的逐曲读音。源文件不会被移动或修改，验证完成后临时副本会立即删除，曲库中只保留自包含的可玩歌曲包。

四种导入方式共同遵循[音乐服务互操作声明](MUSIC-SERVICE-INTEROPERABILITY-NOTICE.md)。

## 歌词、发音与图片来源

- 日语发音优先来自同一首歌曲带时间轴的 QQ 音乐 Roma QRC、网易云 `romalrc` 或酷狗 KRC 的罗马音层，因此歌词作者指定的特殊唱法可以直接保留。`latin-table/` 继承自
  [TypingMania NEO](https://github.com/innocenat/typingmania)，只处理普通歌曲包中的假名，不会推测或覆盖导入歌曲的专属读音。
- 中文拼音由本地的 [`pinyin-pro`](https://github.com/zh-lx/pinyin-pro) 生成。
- 用户主动导入时，对应音乐服务提供用户有权访问的媒体、元数据、官方时间轴歌词和专辑图片；检索会根据地区起始优先级及本次进程中的成功率、失败冷却和响应速度，在 QQ 音乐、网易云音乐、酷狗音乐和 [LRCLIB](https://www.lrclib.net/) 的严格匹配结果间动态排序。
- 曲名、歌手、发行版本及专辑封面还会用 [Apple iTunes Search](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/)、[MusicBrainz](https://musicbrainz.org/doc/MusicBrainz_API) 与 [Cover Art Archive](https://musicbrainz.org/doc/Cover_Art_Archive/API) 交叉核验。只有严格匹配，或两个独立目录对同一修正达成高置信度一致时，才会修改已有曲名或歌手。
- [AniSongDB](https://anisongdb.com/) 与 [AnimeThemes](https://animethemes.moe/) 提供动画歌曲和直接使用作品的精确候选；[AniList](https://anilist.co/) 与 [Bangumi](https://bangumi.github.io/api/) 通过作品 ID、原始语言标题和海报交叉核验。电影和电视剧还可由 Bangumi、[TVmaze](https://www.tvmaze.com/api) 及可选的 [TMDB](https://developer.themoviedb.org/reference/search-movie) 核验。不会用漫画、小说或其它改编前作品冒充直接影视出处。
- [YouTube IFrame API](https://developers.google.com/youtube/iframe_api_reference) 仅用于兼容的 YouTube 歌曲包。

游戏不翻译歌曲名，只显示保存的原始标题。只有能够确认直接出处作品原名时才显示出处，否则留空，避免显示错误的翻译名或原作名。

主要组件和数据来源可在游戏的“关于此游戏”中打开；完整许可证清单见
[第三方声明](THIRD-PARTY-NOTICES.md)。

## 速度、演示与结算

曲目选择页面的速度含义为：

- **整首平均**：在完整可输入时间轴中，每分钟需要输入的字母数。
- **最快 5 秒**：任意连续 5 秒内最高的字母输入速率。

曲目选择、自动演示和结算页面使用相同的字母计数、歌词时间与窗口模型。第一句在 1.5 秒前出现时，会先显示简短的 3–2–1 预备倒计时，但不会移动媒体时间轴。自然完成后保留游玩画面 1.4 秒，再进入结算页面。

## 曲库编辑与重置

“编辑曲目”支持键盘和鼠标多选。确认后，程序会暂存所选歌曲包、重建索引、只删除对应成绩并清理不再引用的私有元数据；如果在提交删除前中断，下次启动会自动回滚。三首示例歌曲不能被单独删除。

“重置曲库”现在会先询问清理范围：可删除全部导入歌曲并恢复三首示例曲，也可只删除 QQ 音乐、网易云音乐、Apple Music 或本地文件夹中的歌曲。仅清理对应成绩与不再引用的元数据，不会修改任何音乐客户端缓存、下载目录、用户选择的源文件夹或浏览器 Cookie 存储。

“更新曲目信息”会重新核验所有已导入歌曲。程序先读取可验证的原服务曲目记录，再用独立音乐目录交叉检查曲名、完整歌手、发行信息和歌词语言；只有严格一致或独立双源高置信度共识才会纠错。动画、电影、电视剧、纪录片、广告片、综艺、体育赛事、视觉小说、JRPG 与游戏的直接出处、作品原名及海报会通过对应目录核验。与已有可靠信息冲突或证据不足的字段和附件一律保持不变或留空。按 `Esc` 或 `Backspace` 会立即中断当前联网阶段，不再等待来源超时；已原子写入的可靠更新仍会保留。

## 网络与部署

启动、菜单、示例歌曲、导入后的本地歌曲、发音、计分、自动演示、按键雨和结算均可离线运行。只有用户主动导入、维护可选元数据/图片、开启 MV 并进入尚无缓存的歌曲，或选择 YouTube 歌曲包时才会访问网络。

程序不会通过 IP 定位用户。它根据系统语言、时区或可选的 `TMN_NETWORK_REGION`（`cn`、`hk`、`tw`、`jp`、`kr`、`sea`、`us`、`eu`、`global`）选择初始路线，然后按实际成功、失败和响应时间动态调整：中国大陆优先 QQ 音乐、网易云音乐、酷狗与 Bangumi；港澳台、日本、韩国、东南亚、美国、欧洲及其它地区会相应提高当地可达的 LRCLIB、iTunes Search、MusicBrainz、TVmaze、TMDB 与 Wikidata 顺序。作品数据依次优先采用音乐服务/官方记录、专业目录、百科交叉证据和官方媒体；媒体平台只作为待核验线索。每个来源都有短超时、有限重试、失败冷却及批次熔断；可选信息始终无法确认时会留空或使用中性内置图片，歌曲只在缺少可玩歌词或可靠读音时才被丢弃。

### 静态部署

```sh
npm run build-game
```

静态文件会生成到 `dist/`，可部署到 GitHub Pages 或其它 Web 服务，并游玩部署中包含的歌曲包。

纯静态网站不能使用音乐服务导入、启动时文件扫描、事务式删除/重置和打包图片提取；这些功能需要本地服务。请勿把私有 `data/` 内容放入公开构建。

## 隐私与公开发布

本地服务只监听 `127.0.0.1`。所有修改数据的接口都需要随机同源令牌。QQ 音乐会话、网易云源文件和 Apple Music Cookie 只用于用户主动发起的本地导入，不写入公开歌曲包、日志或发布文件。

Git 会排除：

- 所有 `QQMusicCache` 目录；
- 网易云 `.ncm`/`.uc`、Apple Music Cookie、临时文件夹副本和对应客户端缓存；
- `data/` 中生成的内容；
- 导入的媒体、歌词、封面、海报、会话、日志和 PID；
- 本地参考图片与环境变量文件。

发布前可运行：

```sh
npm run audit-public
```

审计程序会检查已跟踪及准备发布的未跟踪文件，拦截私有媒体、非示例歌曲包、用户目录、运行状态和常见凭据格式。

## Song Studio

启动本地服务后打开：

## 项目结构

```text
assets/              字体、界面图片和音效的源文件及打包文件
docs/                用户与互操作说明
latin-table/         字符规范化与日语罗马字表
scripts/             构建、审计、本地服务、启动和导入逻辑
scripts/local/       本地曲库模块及测试
songs/               三首公开示例歌曲包
src/                 浏览器游戏、界面、媒体、输入、特效和编辑器代码
tools/importers/     固定版本的网易云与 Apple Music 离线导入组件
tools/runtime/       已校验的 Windows Node.js 运行环境压缩包和许可证
vendor/editor/       本地 Song Studio 浏览器依赖和许可证
vendor/runtime/      固定版本的离线导入依赖和许可证
```

生成的构建、开发依赖、浏览器自动化状态、运行环境解压目录和私有曲库数据都不会纳入版本控制。

## 验证

```sh
npm test
npm run build-game
npm run audit-library
npm run verify-runtime
npm run audit-public
```

`audit-library` 只检查公开发行包中的三首示例曲；如需检查本机私有曲库，请运行 `npm run audit-local-library`。私有曲目不会因此被加入发布文件。

也可以一次运行全部检查：

```sh
npm run check
```

Jest 固定使用单进程，因此测试结束后不会在 Windows 留下工作进程池。
